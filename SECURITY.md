# Security Policy

## Reporting

Use GitHub Private Vulnerability Reporting from the repository Security tab. If that feature is unavailable, open a public issue containing only a request for a private contact channel. Never post credentials, private prompts, conversations, account identifiers, deployment URLs, or exploit details that expose users.

## Supported versions

Only the latest published release receives security fixes until a formal long-term-support policy exists.

## Scope

Reports about secret persistence, command injection, unsafe IPC, unauthorized file access, template disclosure, dependency compromise, or redaction failure are in scope. Third-party platform outages and provider policy disputes should be reported to the relevant provider.
